ESPHome Bluetooth (BLE) Integration for BDR Thermea, De Dietrich, Baxi, Remeha & Brötje Boilers and Heat Pumps

Monitor live temperatures, water pressure, and energy consumption/delivery counters, and edit heating & DHW parameters directly from Home Assistant over Bluetooth Low Energy (BLE) using a standard ESP32 — no proprietary gateway (GTW-08, SMART TC) or wiring required, while keeping your existing OpenTherm / R-Bus room thermostat untouched.

Key Features

100% Wireless over BLE

Connects directly to the appliance's built-in MK3 / EHC-08 / CU-GH08 Bluetooth interface using any ESP32 (ESP32, ESP32-S3, ESP32-C3, ESP32-C6). Your physical R-Bus / OpenTherm / L-Bus terminals stay free.

Dynamic UUIDs, PIN & GTW-IoT Support

Dynamically resolves GATT handles by 128-bit UUID across all boards (EHC-08, EHC-16, CU-*), supports both 6-digit PIN Passkey bonding (MK3 / GTW-22) and PIN-less GTW-IoT hubs, and auto-recovers from stale bonds and 60s lockouts.

Read & Write Support

Read temperatures, pressures, status enums, and kWh energy counters (sensor, binary_sensor, text_sensor), and edit numeric setpoints and operating modes (number, select) via confirmed CANopen writes.

3,092-Datapoint OBD Dictionary

Reference parameters by short installer menu code (AM027, DM001, AC005, DP070), OBD name (varApTotalEnergyDelivery), or hex index (0x5044:00) with zero firmware bloat.

Batch Polling & Auto-Skip

Combines datapoints sharing an update_interval into high-speed GetListRequest (0x08) batches and automatically disables unsupported parameters reported by the boiler.

On-Demand CAN & 0x502B Discovery

Quietly loads 0x502B hardware limits on first boot (persisted to NVS flash for number & select) and provides a button / bdr_ble.discover action to detect all active CAN nodes and dump BDR_SNAPSHOT: lines for the YAML Configurator.

Important Requirements & BLE Pairing Guide

Mandatory ESPHome BLE Settings:
  • Use the esp-idf framework (framework: type: esp-idf).
  • Set io_capability: keyboard_only under esp32_ble: so ESP-IDF can reply to the boiler's 6-digit Passkey Entry pairing prompt.
  • Do NOT enable bluetooth_proxy on the same ESP32 (when active, it suppresses local ble_client device discovery).

Route A: Onboard BLE Module (MK3 / GTW-22 / EHC-* / CU-*) — With 6-Digit PIN

  1. Advertises as: EHC-... or CU-... (with manufacturer data "BDR").
  2. On your boiler / heat pump control panel (HMI), activate Bluetooth pairing mode so the 6-digit PIN code is displayed on the screen (on some units like Remeha Confida 40 / Elga Ace, the static 6-digit PIN is printed on the internal BLE sticker).
  3. Add that 6-digit PIN to your ESPHome secrets.yaml (wrap it in quotes if it starts with 0, otherwise YAML parses it as octal; bdr_ble logs PIN: ****xx at boot so you can verify the last 2 digits): 
    strateo_ble_pin: "012345"
  4. Flash the ESP32 with pin: !secret strateo_ble_pin under bdr_ble:. Upon connecting, bdr_ble automatically bonds using your PIN, saves the LTK key in ESP32 NVS flash, and unlocks Service 3 + CAN-BUS RUB v2.01.

Route B: External GTW-IoT Home Hub — Without PIN

Appliances using the external round GTW-IoT hub (advertising as GTW-IOT_<serial>, e.g., Remeha Elga Ace All-in-One / Confida 10) do not use BLE Passkey encryption. Simply omit the pin: option under bdr_ble: in your YAML, briefly press the button on the GTW-IoT hub to put it into BLE discovery mode, and bdr_ble will connect directly in plain BLE mode and perform the RUB v2.01 TEA unlock handshake. Note: by hardware design, when a BLE client disconnects from the GTW-IoT hub, the hub exits BLE discovery mode until its physical button is pressed again.

Dynamic GATT UUID Discovery & Gateway Auto-Recovery

  • Dynamic GATT Handle Resolution by UUID: Different controller boards (EHC-08, EHC-16, CU-*, GTW-22, GTW-IoT) place the BLE characteristics at different attribute handles. On every connection, bdr_ble dynamically queries the GATT database by 128-bit UUID to resolve the exact characteristic and CCCD handles automatically.
  • 3-Device Bond Limit & Stale Key Auto-Recovery: The appliance's internal BLE gateway (GTW-Blue) stores at most 3 paired devices and silently evicts the oldest bond when a 4th device pairs. If the ESP32's stored bond is evicted (0x61 Encryption Failed), bdr_ble automatically deletes the stale local bond from ESP32 NVS so the next attempt performs a fresh Passkey pairing.
  • 60-Second Gateway Lockout Backoff (0x56 Repeated Attempts): After a failed pairing attempt, the boiler's BLE module rejects all new pairing attempts for 60 seconds. Rather than retrying every few seconds (which would extend the lockout indefinitely), bdr_ble pauses ble_client and waits with exponential backoff (90s → 180s → 300s → 600s), publishing the status and countdown to the BLE Status sensor.
  • Coexistence with the Official Mobile App: Because the boiler accepts only one active BLE connection at a time, include the ble_client switch (Boiler BLE Connect) in your YAML. Turning it Off in Home Assistant releases the BLE link so you can connect with your smartphone.

Quick Start YAML

Add the external component to your ESPHome YAML configuration:

external_components:
  - source: github://d-lebed/esphome-bdr-ble@v1.5.1
    components: [bdr_ble]

esp32:
  board: esp32-c6-devkitm-1
  variant: esp32c6
  framework:
    type: esp-idf

esp32_ble:
  io_capability: keyboard_only

esp32_ble_tracker:
  scan_parameters:
    active: true

ble_client:
  - mac_address: "00:A0:50:XX:XX:XX"
    id: boiler_ble

bdr_ble:
  id: boiler_hub
  ble_client_id: boiler_ble
  pin: !secret strateo_ble_pin
  node_id: 1
  auth_level: 4

button:
  - platform: bdr_ble
    bdr_ble_id: boiler_hub
    name: "Discover CAN Nodes & Snapshot"

switch:
  - platform: ble_client
    ble_client_id: boiler_ble
    name: "Boiler BLE Connect"
    restore_mode: RESTORE_DEFAULT_ON
    entity_category: config

text_sensor:
  - platform: bdr_ble
    status:
      name: "Boiler BLE Status"

3-Step Workflow: Discover All Supported Sensors for Your Boiler

Because BDR Thermea's Object Dictionary contains 3,092 datapoints across dozens of appliance types, each boiler only implements the subset matching its installed hardware. Follow this 3-step workflow to configure your exact appliance:

Step 1: Flash the Minimal Config & Press the Discover Button

Flash the Quick Start configuration above, open the ESPHome logs, and press the Discover CAN Nodes & Snapshot button in Home Assistant (or trigger the bdr_ble.discover action). bdr_ble probes active CAN bus nodes (0x1F85:00 + 0x2001:02), selects V2 descriptors (0x502C → 0x502D), reads 0x502B for every detected board, and prints BDR_SNAPSHOT: lines: 

[I][bdr_ble]: CAN bus nodes present (0x1F85:00=4): [1 (type=...), 4 (type=...)] — scanning 0x502B snapshot on all detected nodes
[I][bdr_ble]: === Appliance Snapshot (290 supported datapoints from 0x502B:01..15) ===
[I][bdr_ble]: BDR_SNAPSHOT:3011:00@1,3012:00@1,3013:00@1,3654:01@1,3655:01@1,...
[I][bdr_ble]: BDR_SNAPSHOT:5013:00@1,5016:00@1,501A:00@1,501E:00@1,5044:00@1,...
[I][bdr_ble]: === End of Appliance Snapshot (paste BDR_SNAPSHOT lines into configurator.html) ===
[I][bdr_ble]: === Appliance Snapshot (Node 4: 10 supported datapoints from 0x502B:01..15) ===
[I][bdr_ble]: BDR_SNAPSHOT[N4]:303E:00@1,3042:00@1,309E:00@1,3047:00@1,...
[I][bdr_ble]: === End of Appliance Snapshot (Node 4) ===

Step 2: Paste the Snapshot into the Interactive YAML Configurator

  1. Open the Interactive ESPHome YAML Configurator.
  2. Paste the raw BDR_SNAPSHOT:... log lines into the Paste BDR_SNAPSHOT:... lines from ESPHome logs box.
  3. The table immediately filters to the exact parameters, live measurements (Signal), and counters (Counter) reported by your boiler.
  4. Select the items you want, choose their polling interval (10s, 30s, 60s), and copy the generated sensor:, binary_sensor:, text_sensor:, number:, and select: YAML blocks.

Step 3: Add Any Extra Internal Counters (Protected by Auto-Skip)

Some internal CANopen datapoints (such as aggregate total energy delivery varApTotalEnergyDelivery 0x5089:00) are supported by the boiler even if they don't appear on the front-panel menu. You can browse all datapoints for your board model in the Configurator and add them freely — if any datapoint is unsupported, bdr_ble logs a single warning and automatically disables polling for it (Auto-Skip).

Configuration Reference

1. Hub (bdr_ble) & Access Levels (auth_level)

bdr_ble:
  id: boiler_hub
  ble_client_id: boiler_ble       # Required: ID of the ble_client entry
  pin: !secret strateo_ble_pin    # Optional: 6-digit BLE pairing passkey (0..999999); omit for GTW-IoT
  node_id: 1                      # Optional: Default CANopen Node ID (default: 1 = main Control Unit)
  auth_level: 3                   # Optional: TEA authorization level 1..4 (default: 4)

button:
  - platform: bdr_ble
    bdr_ble_id: boiler_hub        # Optional when only one hub is defined
    name: "Discover CAN Nodes & Snapshot"   # On-demand CAN node probe + BDR_SNAPSHOT log dump

How auth_level works in the boiler controller:
The boiler's CANopen controller partitions all parameters (0x502B SubIndex 1..5), live signals (SubIndex 6..10), and counters (SubIndex 11..15) into 5 hardware access levels. The boiler itself enforces these permissions: if you configure a lower auth_level (for example, auth_level: 1 or 2), the boiler will refuse both reading and writing any datapoint belonging to a higher level (returning SDO Abort / status = 0x02).

auth_level Role / Level Name 0x502B Tables (Param / Signal / Counter) Accessible Datapoints & Safety Scope (Verified on EHC-08)
1 End User (Safe) SubIndex 1, 6, 11 Only safe user-facing settings and basic telemetry:
• DHW Comfort / Eco / Holiday setpoints (DP070, DP080, DP337), DHW & Zone operating modes (DP200, CP320), weekly schedules
• Basic temperatures & pressure (AM016 flow, AM027 outdoor, BM000/DM001 DHW, AM019 water pressure)
• 14 primary energy & runtime counters (AC001, AC003, AC005–AC007, AC018, AC019, AC032, DC002–DC005, PC000, PC005)
2 Installer — Standard
(90% field settings)		 SubIndex 1..2, 6..7, 11..12 Everything in Level 1, plus standard commissioning parameters & thermal delivery counters:
• Zone max flow setpoint (CP000), heating curve settings (CP230), DHW hysteresis (DP120)
• Thermal energy delivery counters (AC002, AC004, AC008, AC009, AC010, varApTotalEnergyDelivery)
3 Installer — Special / Service
(Recommended for full monitoring)		 SubIndex 1..3, 6..8, 11..13 Everything in Levels 1–2, plus advanced heat pump / hydraulic settings and service counters:
• Bivalent temperature (HP000), pump speed limits (DP037, DP038), backup heater delays (DP090)
• Service counters in SubIndex 13: average COP/performance factor (AC013), pump hours & starts (AC026, AC027), backup 1 hours & starts (AC028, AC030), total heat generator starts & hours (PC002, PC003)
• Keeps Level 4 factory/lab parameters locked by the boiler.
4 Lab Testing / OEM
(Default)		 SubIndex 1..4, 6..9, 11..14 Unlocks all datapoints (Levels 1–4), including low-level factory/OEM inverter, compressor, and PID parameters.
5 Controls Dept Only SubIndex 1..15 Reserved for R&D controls engineering (not used on production boilers).
Tip: The Interactive YAML Configurator displays an L1–L4 badge on every datapoint and automatically calculates the minimum required auth_level for your selected sensors and parameters.

2. Numeric Sensors (sensor)

Supports both grouped batch syntax (sensors: [...]) and single sensor syntax. All datapoints sharing the same update_interval are automatically batched into GetListRequest (0x08) reads. 

sensor:
  # Fast group (polled every 10s in a single GetListRequest batch)
  - platform: bdr_ble
    update_interval: 10s
    sensors:
      - parameter: AM027
        name: "Strateo Outside Temperature"
      - parameter: AM016
        name: "Strateo Flow Temperature"
      - parameter: BM000
        name: "Strateo DHW Temperature"
      - parameter: AM019
        name: "Strateo Water Pressure"

  # Slow group (polled every 60s in a single GetListRequest batch)
  - platform: bdr_ble
    update_interval: 60s
    sensors:
      - parameter: AC005
        name: "Strateo Energy CH Consumption"
      - parameter: AC006
        name: "Strateo Energy DHW Consumption"
      - parameter: AC018
        name: "Strateo Energy Backup Consumption"
      - parameter: AC008
        name: "Strateo Thermal Energy CH Delivery"
      - parameter: AC009
        name: "Strateo Thermal Energy DHW Delivery"
      - parameter: varApTotalEnergyDelivery
        name: "Strateo Total Thermal Energy Delivered"

3. Binary Sensors (binary_sensor)

Supports polling boolean / two-state status signals (such as HM012 / HM013 backup heater stages, AM015 system pump running, HM008 compressor running, HM009 defrost active, or DM000 DHW electrical backup) as Home Assistant binary_sensor entities (0 = OFF, != 0 = ON). 

binary_sensor:
  - platform: bdr_ble
    update_interval: 10s
    binary_sensors:
      - parameter: HM012
        name: "First stage of backup operation"
      - parameter: HM013
        name: "Second stage of backup operation"
      - parameter: AM015
        name: "System pump running"

4. Text Sensors (text_sensor)

Provides the status diagnostic sensor and decoded Enum, VisibleString, OctetString, and TimeOfDay datapoints: 

text_sensor:
  - platform: bdr_ble
    status:
      name: "Strateo BLE Status"

  - platform: bdr_ble
    update_interval: 30s
    sensors:
      - parameter: AM012
        name: "Strateo Appliance Status"
      - parameter: AM014
        name: "Strateo Appliance Sub-Status"

Editing Boiler & Heat Pump Parameters (number & select)

5. Writable Numeric Parameters (number)

Supports editing writable numeric parameters (U8, I8, U16, I16, U32, I32, such as DHW comfort/eco setpoints, heating curve slopes, or zone flow setpoints). When the boiler connects and reports its 0x502B descriptors, bdr_ble dynamically updates each number entity's min_value, max_value, and step to the exact hardware limits of your boiler, persists them in ESP32 NVS flash so Home Assistant sees them immediately on subsequent boots, and rejects out-of-range writes locally (disable per entity with device_limits: false). 

number:
  - platform: bdr_ble
    update_interval: 30s
    numbers:
      - parameter: DP070
        name: "Strateo DHW Comfort Setpoint"
      - parameter: DP080
        name: "Strateo DHW Eco Setpoint"
      - parameter: CP010
        name: "Zone 1 Flow Temperature Setpoint"

6. Writable Enum Parameters (select)

Supports editing enumerated parameters (such as DHW operating mode or heating zone mode). Dropdown options are populated automatically at compile time from obd_catalog.json, dynamically filtered against the boiler's 0x502B hardware range, and persisted in ESP32 NVS flash (disable per entity with device_limits: false). 

select:
  - platform: bdr_ble
    update_interval: 30s
    selects:
      - parameter: DP200
        name: "Strateo DHW Operating Mode"
      - parameter: CP320
        name: "Zone 1 Operating Mode"

7. Writable String Parameters (text)

Supports reading and editing writable VisibleString parameters (such as zone friendly names parZoneFriendlyName, user activity names parZoneFriendlyNameUserActivity, appliance name parApApplianceName, and installer details AP089 / AP090) with automatic character length limits from obd_catalog.json. (Note: parZoneFriendlyNameShort / 0x3410 is a read-only hardware terminal label such as CIRCA and should be polled via text_sensor.) 

text:
  - platform: bdr_ble
    update_interval: 30s
    texts:
      - parameter: parZoneFriendlyName
        name: "Zone 1 Friendly Name"
      - parameter: parZoneFriendlyNameUserActivity
        sub_index: 1
        name: "Activity 1 Name"

8. On-Demand Discovery (button & bdr_ble.discover Action)

Triggers an on-demand CAN bus node scan (0x1F85:00 + 0x2001:02) and logs BDR_SNAPSHOT: / BDR_SNAPSHOT[N<id>]: for every detected node, instead of dumping snapshots on every BLE reconnect. Can be configured as a button entity or invoked from any ESPHome automation via bdr_ble.discover: 

button:
  - platform: bdr_ble
    bdr_ble_id: boiler_hub              # Optional when only one hub is defined
    name: "Discover CAN Nodes & Snapshot"

# Or trigger from any ESPHome automation / template button:
#   on_press:
#     - bdr_ble.discover: boiler_hub

Frequently Asked Questions (FAQ)

Can I use Bluetooth (bdr_ble) at the same time as an OpenTherm or R-Bus thermostat?

Yes! Because bdr_ble communicates wirelessly over the boiler's built-in Bluetooth Low Energy interface, your physical R-Bus / OpenTherm / L-Bus terminals remain untouched. You can keep an ESPHome OpenTherm shield or physical room thermostat connected on the wired bus while using bdr_ble to read energy counters, water pressure, DHW tank temperature, and edit installer parameters.

Do I need a BDR Thermea GTW-08 gateway, SMART TC, or extra hardware?

No. Any standard ESP32 board (such as ESP32-C6, ESP32-S3, or ESP32-WROOM) placed near the boiler connects directly to the built-in BLE module — the same interface used by installers with the De Dietrich PRO / Baxi / Remeha Service Tool smartphone app.

How do I find my boiler's Bluetooth MAC address?

Enable esp32_ble_tracker: in ESPHome or check any Bluetooth scanner app while near the boiler. BDR Thermea appliances advertise with a name starting with the controller board code followed by the serial number (for example EHC-08_... or CU-GH08_...) and manufacturer data "BDR" (0x42 0x44 0x52), typically with a MAC prefix 00:A0:50:XX:XX:XX.
